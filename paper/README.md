template supplied for the submission. Submit a `.docx`; each `.pdf` is a
LibreOffice render for review only.

| File | Pages | Built from |

loses is argument, not evidence: Related Work folds from five subsections into

lose roughly half their length. Both tables of results and the detector-comparison

## Where the numbers come from

| Claim | Source |
| --- | --- |
| 86 cases, 3 projects, 40 rules, category counts | `specdrift build` over `cases/*.yaml` |
| Test-escape rates (Table III) | the `escapes_tests` label the builder writes per case |
| Recall@1/3/5 (Fig. 1) | `specdrift retrieval-eval`, local hashing embedder, k = 5 |
| Keyword baseline row and per-category recall | `specdrift run --detector keyword` then `specdrift score` |
| SpecGuard and whole-file rows (Table IV, Fig. 2) | run 1 of the `gpt-4o-mini` runs frozen in `../results-snapshot/annotated/` |
| Strict precision (SP column) | `strict_precision` in each detector's `metrics.json`; off-target flags counted as false positives |
| 95% intervals, run-to-run spread, 5% outcome flips | `specdrift stability`, saved as `stability.json` beside each detector's metrics |
| Rule-id ablation (Section VII) | `../results-snapshot/no-rule-ids/` |
| Oracle confirmation (12 of 13) | `specdrift oracles`, saved as `../results-snapshot/oracles.json` |

The bars in Fig. 2 are run 1; the whiskers are the bootstrap intervals, hard-coded in
`build/figs.py` from the snapshot. Re-score any of it without a key by copying a
detector's `verdicts.jsonl` into `results/<detector>/` and running `specdrift score`; only
regenerating the verdicts needs an API key.

## Rebuilding

```bash
pip install python-docx matplotlib
cd paper/build
python normalize.py conference-template-a4.docx template_fixed.docx   # once
python figs.py
python build_paper.py                                      # six pages
PAPER_CONTENT=content_short PAPER_OUT=../SpecDrift-Bench_IEEE_paper_4pp.docx \
  python build_paper.py                                    # four pages
```

`normalize.py` exists because the supplied template declares the OOXML namespaces
under their `purl.oclc.org` aliases, which `python-docx` does not recognise. It
rewrites them to the `schemas.openxmlformats.org` forms and changes nothing else;
Word and LibreOffice treat the two as equivalent.

`content.py` and `content_short.py` hold the text, tables and figure captions;
`content_short.py` imports the title and author block from `content.py`, so those
are defined once. The template's own styles
supply all numbering — section numerals, `TABLE I.`, `Fig. 1.` and `[1]` are
generated by Word, so none of them is typed in `content.py`.
