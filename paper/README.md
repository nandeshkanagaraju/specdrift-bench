# Paper

`SpecDrift-Bench_IEEE_paper.docx` is the manuscript, written into the IEEE A4
conference template supplied for the submission. `SpecDrift-Bench_IEEE_paper.pdf`
is a LibreOffice render of it, for review only — submit the `.docx`.

## Confirm before submitting

- **Affiliations and e-mail addresses** were inferred from the register numbers on
  the abstract sheet and are the one part of the document that was not taken from
  the repository or the cited sources. Check all four.
- The conference may cap the page count; the manuscript is six pages.

## Where the numbers come from

| Claim | Source |
| --- | --- |
| 86 cases, 3 projects, 40 rules, category counts | `specdrift build` over `cases/*.yaml` |
| Test-escape rates (Table III) | the `escapes_tests` label the builder writes per case |
| Recall@1/3/5 (Fig. 1) | `specdrift retrieval-eval`, local hashing embedder, k = 5 |
| Keyword baseline row and per-category recall | `specdrift run --detector keyword` then `specdrift score` |
| SpecGuard and whole-file rows (Table IV, Fig. 2) | the `gpt-4o-mini` run reported in the root `README.md` |

The SpecGuard and whole-file figures need an API key to reproduce; everything else
runs offline.

## Rebuilding

```bash
pip install python-docx matplotlib
cd paper/build
python normalize.py conference-template-a4.docx template_fixed.docx   # once
python figs.py
python build_paper.py
```

`normalize.py` exists because the supplied template declares the OOXML namespaces
under their `purl.oclc.org` aliases, which `python-docx` does not recognise. It
rewrites them to the `schemas.openxmlformats.org` forms and changes nothing else;
Word and LibreOffice treat the two as equivalent.

`content.py` holds the text, tables and figure captions. The template's own styles
supply all numbering — section numerals, `TABLE I.`, `Fig. 1.` and `[1]` are
generated by Word, so none of them is typed in `content.py`.
